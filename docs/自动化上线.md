# 自动化上线

确认稿之后的这一段可以一条命令走完：读稿、TTS 预处理、出声、缝开场和片头、响度、Show Notes、节目页、`episodes.json`、用仓库里的 `scripts/rss_gen.py` 写 `feed.xml`。默认是彩排。没有 Joyce 明确说可以上线，就不会调用 ListenHub，也不会改线上 feed。

工厂里那份旧的 `rss_gen.py` 仍然不能拿来覆盖站点 `feed.xml`。这条流水线只用本仓库的 `scripts/rss_gen.py`。

## 现在机器做的

- 读 `queue/<短名>/` 或内置彩排样本 `pipeline/samples/rehearsal-doordash/`（短口播 DoorDash）。
- 预处理：跳过审核附件、生词表、生词好句、命中表、编辑部备注；中文数字改成口播（年份逐位，`400亿` 读四百亿，`2800万` 读两千八百万，不把 `$1美元` 叠读）；英文整句不改数字；`## 英文原文与讲解` 和 `###` 小标题挂到后面那句中文的末尾；去掉英文口头禅（`feel like`、`kind of need` 这种留下）。
- 质检不过就停，不去出声。
- 出声走提供者接口。彩排用 `mock`：每段一个短提示音，不联网。
- 片头 `assets/intro.mp3` 做 1.2 秒交叉淡化，开场两句硬接在正文前，正文段之间硬拼，再响度到 -14 LUFS，导出 192k mp3。
- 按五节模板写公开 Show Notes（没有延伸阅读材料就不写第 4 节）。不写飞书链接，不写导读钩子。
- 在一个临时站点目录里跑真正的 `scripts/rss_gen.py`。

## 仍然要人做的

- 选题、写初稿、改判断。
- 核查精讲稿，并说出「确认上线」。飞书里有稿子不算确认。
- 飞书归档、邮件、小宇宙后台操作。小宇宙自己拉 `feed.xml`。
- 宣发（小Fa）和听友群材料（小Si）。
- 把 GitHub Secrets 配上。流水线不会替你发明 key。
- 开场成片。固定两句应复用 `assets/opening-zh.mp3`（EP20 定稿）。仓库里现在没有这个文件，彩排用提示音占位。真上线前请把那条成片放进来，不要每期重录开场。
- 21:00 之后不上线，这仍是人工约定，工作流不会替你看钟。

## 需要加的 Secrets

仓库是公开的。在 GitHub → Settings → Secrets and variables → Actions 里新增，不要写进文件，不要贴进工作台：

| Secret | 做什么 |
|---|---|
| `LISTENHUB_API_KEY` | ListenHub / Marswave 的 API key（一般是 `lh_sk_` 开头） |
| `LISTENHUB_CLIENT_ID` | 原来写在 `scripts/publish_episode.py` 里的 client id。代码里已经删掉。从你自己电脑上的旧脚本或 ListenHub 开放平台抄进 Secret |

音色 ID 已经在 `episodes.json` 的 `speaker_id` 里，不是 Secret。真上线前仍要按 SOP 当场核对音色，对不上就停。

`scripts/publish_episode.py` 现在也只从 `LISTENHUB_CLIENT_ID` 读。本机要跑旧脚本时，同样导出这两个环境变量，并设置 `CONFIRMED=yes`。

## 彩排

合并这个 PR 之前，看本 PR 的 Actions：`rehearsal` 会跑测试和内置彩排，构件名叫 `podcast-dry-run`。里面有提示音 mp3、`spoken.txt`、Show Notes，以及一份只存在于构件里的 `site/feed.xml`。线上文件不会变。

本机：

```bash
python3 -m scripts.pipeline.publish --sample --mode dry-run --out artifacts/dry-run
```

`artifacts/` 被 gitignore，不会被提交。

对某一期彩排：把稿放进 `queue/<短名>/script.md` 和 `meta.json`（字段见 `queue/README.md`），然后：

```bash
python3 -m scripts.pipeline.publish --input queue/<短名> --mode dry-run --out artifacts/queue-dry-run
```

工作台在 `/workbench/`。「确认上线」打开的是 GitHub Actions 的手动运行页，或复制一条 `gh` 命令。页面里没有 token。手动运行的默认值是 `mode=dry-run`、`confirmed=no`。

注意：GitHub 要等这个工作流文件在 `main` 上，Actions 页面才会出现「Run workflow」。合并前先看 PR 的 CI 和构件。

只扫现有节目、不做出声：

```bash
python3 -m scripts.pipeline.qc --report-only --report /tmp/qc.md
```

发现写在 `docs/质检发现.md`。有阻断时这个命令仍退出 0。新稿上线走的是严格模式，不过就失败。

刷新工作台（只读仓库，不改发布文件）：

```bash
python3 workbench/build.py
```

企业卡在工作台的「企业追踪」。底稿、未公开和过期名单见 `docs/企业追踪.md`。刷新过期名单：

```bash
python3 scripts/companies_refresh.py
```

## 以后怎么真上线

1. 稿子你已经核查过。
2. `queue/<短名>/` 推到 `main`（或你指定要发布的分支）。`id` 不要用 `ep-900`，标题不要以 `[彩排]` 开头。
3. 打开 Actions → `podcast-pipeline` → Run workflow。
4. `mode` 选 `publish`，`confirmed` 填 `yes`，`queue_path` 填 `queue/<短名>`。
5. 工作流会先再跑一遍彩排测试。然后才允许 ListenHub（`mode=direct`，不走 deep），写 `audio/`、`shownotes/`、`episodes.json`，跑 `scripts/rss_gen.py`，提交并推送当前分支。

同一期 id 已经在目录里时，默认拒绝覆盖。要换文件再推，需要另外把环境变量 `REPLACE_EPISODE=yes` 配进那次运行（工作流表单里没有这个开关，避免误覆盖）。

本机真上线等价于：

```bash
CONFIRMED=yes ALLOW_LISTENHUB=yes PUBLISH_MODE=live \
  LISTENHUB_API_KEY=... LISTENHUB_CLIENT_ID=... \
  python3 -m scripts.pipeline.publish --input queue/<短名> --mode live
```

少任何一道闸，命令都会停。彩排样本不能走这条路。

## 回滚

彩排：删掉 Actions 构件或本地 `artifacts/` 即可。没有推到 `main`，小宇宙看不到。

真上线已经推上去：

1. `git revert` 那次「上线」提交，再推 `main`。这样 `feed.xml`、节目页、`episodes.json` 和音频一起回到上一版。
2. 若只想撤一期：把该期在 `episodes.json` 里的那一行、`shownotes/<id>.html`、`audio/<file>`、`ep-<id>.html` 恢复成上一提交，再跑 `python3 scripts/rss_gen.py` 后提交。不要用工厂的短简介版 `rss_gen.py`。
3. 小宇宙如果已经抓到错误文件：沿用以前的做法，换回旧 mp3 并让 enclosure 的字节数、时长和真实文件一致；需要它重抓时再改 `guid`。先改目录和文件，再生成 feed。
4. 不要为了「修」`docs/质检发现.md` 里那 9 项去改历史音频或 feed，除非你单独决定要修。

## 不要做的事

- 不要把 API key 或 client id 写回仓库。
- 不要在未确认时把 `ALLOW_LISTENHUB=yes` 留在环境里。
- 不要把彩排样本 `ep-900` 合并进线上 `episodes.json`。
- 不要在 21:00 之后点真上线。
